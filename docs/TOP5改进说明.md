# TOP5 荐股质量改进 · 落地说明

> 依据对 `src/bottom_fishing_strategy.py` 荐股质量的评价（`粘贴文本.txt`），本轮实现评价建议中最值得先做的五项改进。
> 目标：**宁可少荐，也不让数据缺失提升入选机会**；让推荐理由「说得准」，而不是「过得了条件」。

## 一、总览：五项改进与实现位置

| # | 改进项 | 核心变化 | 主要文件 |
|---|--------|----------|----------|
| 1 | **数据缺失分层** | 财务/周线数据缺失不再「放行即通过」，改判为**待核验候选**；主源财务按字段用 AkShare 补齐后复核 | `src/bottom_fishing_strategy.py`、`run.py`、`notify/feishu.py`、`store/mysql_store.py` |
| 2 | **修正底背离** | 指标比较锚定在「前一个价格低点」当根，而非指标自身窗口最小值；至少间隔 5 根保证是两个独立低点 | `src/bottom_fishing_strategy.py` |
| 3 | **统一评级含义** | 等级=原始技术分定级（删除底背离升档、删除熊市扣分定级改为抬门槛）；结果拆三维展示；排序加股票代码末级键 | `src/bottom_fishing_strategy.py`、`notify/feishu.py` |
| 4 | **细化量价质量** | 二元「量价配合 25 分」→ 三档质量分（放量企稳 25 / 放量上涨 18 / 放量冲高回落 10） | `src/bottom_fishing_strategy.py` |
| 5 | **数据时效与可复现** | 个股最新K线须与沪深300最新交易日一致（停牌→暂不推荐）；周线须覆盖最新交易周；排序确定性；市场环境「未知」明示 | `src/bottom_fishing_strategy.py` |

## 二、逐项说明

### 1. 数据缺失分层（评价第二节）

**问题**：`check_fundamentals` 空数据放行、周线缺失放行、MACD/KDJ 缺失放行，导致「数据完整通过」与「数据缺失没查」拿到同样的评分与等级；且主源 Baostock 返回 ROE+负债率即停止备用查询，商誉/扣非永远为 None，「四项防雷」实际只有两项生效。

**实现**：
- 新增核验状态：`fund_status`（verified / partial / missing）、`weekly_status`（confirmed / unverified / disabled）、`missing_tags`（缺项标签）、`tier`（formal / pending）。
- `_fund_verify_state()`：核心项（ROE+负债率）齐备 → verified；缺其一 → partial；无数据 → missing。商誉/扣非为**可选**，缺失只记标签不降级。
- `_fill_optional_fundamentals()`：**仅对决赛圈**调用 AkShare 按字段补齐商誉/扣非（及缺失核心项），只填 None、不覆盖主源，补齐后重新终审（可被商誉/扣非否决）。放在决赛圈而非全市场，是为控制 AkShare 调用成本。
- 主流程分层：财务或周线数据缺失 → 进入 `pending_out`（待核验候选），**不占正式推荐名额、不落库、不参与追踪、不与正式推荐混排**；飞书卡片独立区块展示并说明缺什么。

**效果**：数据缺失不再提升入选机会；正式推荐 = 核心财务已核验 + 启用的周线已确认 + 行情日期在场。

### 2. 修正底背离（评价第三节）

**问题**：旧逻辑比较「今日 RSI/DIF vs 窗口内指标最小值」，而指标最低点未必出现在前一个价格低点，会把不同低点之间的比较误标为底背离；且该标签还会把 B 级抬成 A 级。

**实现**：`_divergence_confirmed()`
1. 今日收盘须创近 `DIVERGENCE_LOOKBACK`(20) 根新低；
2. 在窗口 `[t-20, t-5]` 内找收盘最低的 bar 作为前一个价格低点（排除近 `DIVERGENCE_MIN_SEPARATION`(5) 根，保证两个独立低点）；
3. 比较**前低点当根**的 RSI/DIF：价格更低 + RSI 高出的幅度超 `DAILY_RSI_DIVERGENCE_THRESHOLD`(2.0)（或 DIF 超 `DAILY_MACD_DIVERGENCE_THRESHOLD`）→ 背离成立；任一侧指标 NaN → 不认定（标签宁缺毋滥）；
4. 背离须出现在近 3 根内且当根有右侧企稳确认（MACD金叉 / RSI超卖反弹 / MA5拐头）→ 输出「已确认底背离」。

同时**删除底背离升档**（`DIVERGENCE_GRADE_LIFT` 移除），底背离降为形态标签 + 同分排序优先项。

### 3. 统一评级含义（评价第四节）

**问题**：同分不同理由、A 级来源不统一（原始高分 / 65 分升档）、分数与展示等级脱节（熊市按 `分数-10` 定级但展示原始分）、排序缺末级键。

**实现**：
- 等级与展示分数**同源**：`grade = _grade_from_score(原始分)`；底背离不再升档。
- 熊市改为**抬高准入分数线** `required = 门槛分 + BEAR_GRADE_BOOST`（等价旧行为、口径透明，不再出现「88 分却是 B 级」）。
- 三维展示：① 基础评分/等级；② `signals_hit` 入选依据（实际触发的条件，量价按档措辞）；③ 核验状态（财务/周线/缺项）。
- `_rank_signals()`：评分降序 → 底背离 → 盈亏比 → **股票代码升序**（末级键），两次运行结果可复现。

### 4. 细化量价质量（评价第五节）

**问题**：只要求「收盘高于昨日 + 量比 ≥1.2」，高开冲高回落的长上影线也拿满 25 分。

**实现**：`_vol_price_quality()` 在基础条件之上按 **收盘位置 `(close-low)/(high-low)`、实体方向、上影线占比** 分档：
- 25 分「放量企稳」：阳线 + 收盘位置 ≥0.6 + 上影线 ≤0.35
- 18 分「放量上涨」：一般情形
- 10 分「放量冲高回落」：收盘位置 <0.35，承接弱——**只降分不否决**

用现有 OHLCV 即可计算，无需扩展数据源；`signals_hit` 措辞随之区分。

### 5. 数据时效与结果可复现（评价第六节 / 收尾五项）

**实现**：
- **个股行情时效**：以沪深300最新交易日为基准，个股最新K线日期不一致 → `FAIL_STALE` 暂不推荐（停牌/数据滞后不再照常评估）。指数取不到时打印告警并跳过校验。
- **周线时效**：最后一根周线 bar 日期须 ≥ 最新交易日所在周的周一，否则不足以作为「当前」趋势确认 → 待核验。
- **周线开关独立**：`REQUIRE_WEEKLY_TREND` 与 `REQUIRE_WEEKLY_MACD_STABLE` 独立生效（旧实现关掉 MA 检查会连带跳过 MACD）。
- **市场环境**：数据不足/获取失败时明示「未知（…）」，不隐含为正常。
- **确定性排序**：末级股票代码键 + `kind="mergesort"`。

## 三、验证

- **单元测试** `test_entry_filters.py`：15 个入场场景 + 68 项断言，**68/68 通过**（新增 33 项覆盖分层、时效、双低点背离正/反例、量价分档、评级同源与熊市门槛、排序可复现、周线数据充分性、三维展示）。
- **主流程端到端冒烟**（打桩数据源，不访问网络）：
  - 周线路径：财务完整 → formal（weekly_status=confirmed）；财务缺失 → pending；周线缺失 → pending；可选项缺失只记 `missing_tags`。
  - 周线禁用路径：weekly_status=disabled，财务缺失者仍不进正式名单。
- **编译校验**：`src/bottom_fishing_strategy.py`、`store/mysql_store.py`、`notify/feishu.py`、`run.py`、`test_entry_filters.py`、两个入口脚本全部通过。

## 四、兼容性与迁移

- `evaluate()` 新增 `latest_trade_date` 关键字参数（默认 None，跳过校验）——旧调用不受影响。
- `main()` 新增可选 `pending_out` 列表参数（默认 None）——不传即旧行为。
- MySQL：新增 `signals_hit` / `fund_status` / `weekly_status` / `rec_tier` / `missing_tags` 五列；首次连接自动建表，并对**存量表**按 `information_schema` 探测后 `ALTER TABLE ... ADD COLUMN`（幂等，失败仅告警不阻断）。
- 已落库的历史记录新列为 NULL，归因脚本按原字段聚合不受影响。
