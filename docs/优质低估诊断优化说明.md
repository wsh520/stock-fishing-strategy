# 优质低估策略：诊断优化与离线验证

## 本次范围

用户确认：优质低估主池排除已识别金融股；其他优化采用推荐A，以诊断、分层、离线对照为主，不自动放宽正式推荐资格。

- 金融排除仅作用于 `_screen_quality_pool` 的内置优质低估评估器。名称关键词和代码名单沿用现有 `_is_financial_stock`，不是完整行业分类器；识别漏项仍需后续核验。
- 自定义评估器（长期、放量突破等）保留原股票池；底层 `evaluate_quality_value` 的金融专项逻辑保留兼容。
- 非金融默认MA20止跌条件、技术分40门槛、近期底部5～40/60参数、经营弱阻断、估值、年度质量和风险阈值均不放松。
- 不运行生产取数/写库/推送，不把离线技术观察集称为完整策略回测。

## 生产日志与状态变化

实现位于 [主策略](<../src/screening_engine.py>)。

### 股票池与最终漏斗

- `QV_UNIVERSE`：原始股票池、金融排除数、实际筛选数。
- `QV_FINANCIAL_EXCLUDED`：排除名称与代码。
- 最终分层分别报告：候选、资格通过、冷却转出、普通待核验、观察合计、冷却后正式。
- `QV_DELIVERY_SUMMARY`：行业去重及名额限制之后的最终可推送数。
- `QV_PENDING_SUMMARY` 的组合合计只对应普通待核验，不含已通过资格的冷却转出。

举例（非本次实时重跑结果）：若候选57、普通待核验56、资格通过1且该票命中冷却，报告为资格通过1、冷却转出1、观察合计57、最终可推送0，不再声称资格通过0。

冷却转出的记录不改原始frame；复制记录后设置：

```text
tier=pending
qualification_status=passed
delivery_status=cooldown
missing_tags追加repeat_cooldown
cooldown_days=10（采用实际配置）
```

普通待核验输出附加 `qualification_status=blocked`、`delivery_status=pending`。冷却期和资格本身未改变。

### 技术与底部诊断

- `QV_PENDING_TECH`：趋势、动量、量价三个分项，以及MA20价格/评分斜率、MA20止跌确认、MA60位置、MACD改善、近期无新低等判据。
- `technical_diagnostics` 仅供日志，`Signal.to_dict()` 剔除它，不向持久化/卡片传播大对象。
- `QV_PENDING_BOTTOM` 新增“全部问题”，可同时出现 `too_old,overextended`。
- 底部原 `status/reason/anchor/gain_pct` 不变；仍按原顺序决定pending或硬否决。增加独立诊断不等于启用独立超涨硬门。

### 经营分层

实现位于 [经营证据](<../src/recent_operating.py>)，在 `QV_PENDING_EVIDENCE` 中以 `signal_profile` 展示。

| 层级 | 描述性规则 |
|---|---|
| 严重恶化 | 原证据status=failed |
| 证据不足 | 原证据不为verified/weak，或信号无法归类 |
| 多项恶化 | 原reasons涉及两个以上不同指标；累计与单季同一指标只计一次 |
| 单项波动 | 原reasons涉及一个指标 |
| 恢复中 | 仅非正基数转正、没有其他下降信号 |
| 未见明显走弱 | 原证据没有不利信号 |

另附 `recovery_evidence`：仅累计收入/净利/扣非承压、所有受影响指标的最新单季同比均有效且>0、无其他弱信号时，标记“累计承压·最新单季恢复”。缺失、NaN、无增长或同时存在现金流/利润率走弱，不会得到该恢复标记。

这些字段不参与资格、分数或排序，不替换原 `status/reasons`。旧经营缓存可直接依据原证据补充描述，无需为描述重新取数。

### 商誉缺失诊断

实现位于 [财务风险](<../src/financial_risk.py>)，以 `goodwill_diagnostics` 展示：

- `absent`：没有精确匹配的商誉字段；不据此猜测企业没有商誉。
- `empty_or_non_numeric`：字段存在但为空/非数值。
- `duplicate`：多条同名字段，保持歧义未知。
- `explicit_zero` / `valid`：明确零 / 有效正数。
- `invalid_negative` / `no_report`：负值 / 没有可用报告。

包含字段次数、解析值、最多3条各80字符的原始短样本及来源；不输出整个报表。canonical行的回退诊断不能恢复已经丢失的原始信息，明确标为 `canonical_row`。

财务风险缓存升级至v3，旧v2缓存不会假装拥有原始字段诊断。下次正常生产执行可能重新请求一次这部分财务证据。未发现有证据支持的“明确零被吞”解析错误，因此没有擅自补零或放宽字段匹配。

### 闸门审计

实现位于 [审计模块](<../src/qv_diagnostics.py>)。

`QV_GATE_AUDIT` 按每只股票合并廉价预筛与财务复筛的“进入检查”集合，区分：

- 未启用；
- 本策略不适用；
- 已进入检查但未否决；
- 未进入（前置返回或适用条件未满足）；
- 运行异常（ERROR，不是选股闸门）。

“进入检查”不是该闸门所有子条件均完整执行，更不是独立风险贡献；首因否决仍受顺序影响。上下文线程隔离，异常退出会清理上下文。自定义评估器未接入时明确提示，不虚构执行量。

## 影子底部与技术消融

[工具](<../diag_technical_bottom_ablation.py>)、[详细使用说明](<离线技术消融与底部影子诊断.md>)。

- 影子局部底/二次底先截断到决策日，不用未来数据确认历史信号。
- 明确确认日、失效日，不自动替换生产最低收盘价锚点。
- 二次底不通过挑选较高锚点压低涨幅；保留第一底与支撑位参考。
- 三个技术对照组：止跌且技术分≥40、仅止跌、仅技术分≥40。
- 末日无成交跳过；历史和前瞻均按有效成交bar计数；未来数据只生成前瞻收盘收益标签，不进入特征。
- 未重建财务/估值/风控候选总体、未加入交易成本和成交模型；本地CSV仅含代码时也未实施按名称识别的金融排除（示例缓存可能含银行），不能作为完整生产策略收益。
- 即使达到样本数/日期数门槛，也只输出描述统计，不自动改变生产默认。

复现示例：

```powershell
.\.venv\Scripts\python.exe diag_technical_bottom_ablation.py --input backtest_cache/daily --as-of 2025-03-31 --as-of 2025-04-30 --as-of 2025-05-30 --as-of 2025-06-30 --as-of 2025-07-31 --as-of 2025-08-29 --limit 100 --output .test-artifacts/qv_technical_multidate.json
```
