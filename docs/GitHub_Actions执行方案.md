# GitHub Actions 执行方案说明

## 两种执行方式

长期优质低估低位策略**支持独立执行**，也可以与原策略一起执行。推荐**独立执行**。

---

## 方案一：独立执行（推荐）✅

### 优点
- ✅ **时间错开**：原策略21:00，长期版21:30，避免同时抢占资源
- ✅ **缓存隔离**：两套策略使用不同缓存key，互不干扰
- ✅ **失败隔离**：一个失败不影响另一个
- ✅ **通知分离**：飞书卡片分别推送，标题清晰区分
- ✅ **易于维护**：可独立调整执行时间、参数、开关

### 配置文件
已创建 `.github/workflows/daily_screen_longterm.yml`

### 执行时间
```yaml
schedule:
  - cron: '30 13 * * 1-5'  # 北京时间21:30（比原策略晚30分钟）
```

### 工作流概览
```
21:00 - 原策略 (daily_screen.yml)
  └─ 优质低估低位 (quality_value)
  └─ 放量突破 (volume_breakout)
  └─ 推荐5/4/2只，持有10-20天
  └─ 飞书通知：【优质低估低位】/ 【放量突破】

21:30 - 长期版 (daily_screen_longterm.yml) ← 新增
  └─ 长期优质低估低位 (quality_longterm)
  └─ 推荐3/2/1只，持有30-90天
  └─ 飞书通知：【长期优质低估低位】
```

### 落库区分
```python
# 原策略
strategy="bottom_fishing"  # 或 "volume_breakout"

# 长期版
strategy="longterm_quality"  # 独立策略标识

# 数据库中可通过 strategy 字段区分
SELECT * FROM stock_recommendation 
WHERE strategy = 'longterm_quality'  -- 长期版推荐
```

## 方案二：合并执行（不推荐）

### 如果要合并到原 daily_screen.yml

#### 修改 `.github/workflows/daily_screen.yml`
```yaml
jobs:
  daily-screen:
    steps:
      # ... 原有步骤 ...
      
      # 原策略执行
      - name: Run quality_value + breakout
        run: |
          python run.py
          python run_breakout.py
      
      # 新增：长期版执行
      - name: Run long-term quality (optional)
        if: always()  # 即使原策略失败也运行
        run: python run_longterm.py
```

### 缺点
- ❌ 一个失败可能影响整个workflow
- ❌ 执行时间更长（可能超timeout）
- ❌ 缓存可能冲突（虽然有meta验证，但增加复杂度）
- ❌ 日志混在一起，不易排查

## 推荐配置：独立执行

### 1. 启用长期版workflow
```bash
# 文件已创建：.github/workflows/daily_screen_longterm.yml
# 提交到GitHub即可自动生效
git add .github/workflows/daily_screen_longterm.yml
git commit -m "feat: 添加长期优质低估低位策略独立workflow"
git push
```

### 2. 在GitHub仓库中查看
```
仓库 → Actions → 左侧会出现：
  - Daily Stock Screening (原策略)
  - Daily Stock Screening (Long-term Quality) (新增)
```

### 3. 手动触发测试
```
Actions → Daily Stock Screening (Long-term Quality) → Run workflow
  ✓ 勾选 compare_mode（对比原策略与长期版）
  ✓ 勾选 no_save（不落库，测试用）
  ✓ 点击 Run workflow
```

## 数据库查询示例

### 区分不同策略的推荐
```sql
-- 查看今日所有策略推荐
SELECT 
    strategy,
    COUNT(*) as count,
    AVG(score) as avg_score
FROM stock_recommendation
WHERE rec_date = CURDATE()
GROUP BY strategy;

-- 结果示例：
-- strategy            | count | avg_score
-- bottom_fishing      | 5     | 72.3
-- volume_breakout     | 3     | 68.5
-- longterm_quality    | 3     | 80.2  ← 长期版
```

### 查看长期版历史推荐
```sql
SELECT 
    rec_date,
    code,
    name,
    score,
    quality_score,
    valuation_score,
    signals_hit
FROM stock_recommendation
WHERE strategy = 'longterm_quality'
ORDER BY rec_date DESC, rank_score DESC
LIMIT 20;
```

## 推荐配置总结

### ✅ 方案一：独立执行（强烈推荐）

**优势**：
1. 时间错开避免冲突
2. 失败隔离保证稳定性
3. 缓存独立提高效率
4. 通知清晰便于区分
5. 易于独立调整参数

**配置**：
```bash
# 1. 提交新workflow
git add .github/workflows/daily_screen_longterm.yml
git commit -m "feat: 添加长期优质低估低位策略"
git push

# 2. 在GitHub Actions中会自动生效

# 3. 首次运行建议手动触发测试
#    Actions → Daily Stock Screening (Long-term Quality)
#    → Run workflow → ✓ compare_mode
```

### ❌ 方案二：合并执行（不推荐）

仅在以下情况考虑：
- 只想维护一个workflow文件
- 不在乎执行时间变长
- 不担心失败连锁反应

---

## 最终建议

**采用方案一（独立执行）**：

1. **原策略保持不变**
   - `.github/workflows/daily_screen.yml`
   - 北京时间21:00
   - 优质低估低位 + 放量突破

2. **新增长期版workflow**
   - `.github/workflows/daily_screen_longterm.yml`（已创建）
   - 北京时间21:30
   - 长期优质低估低位

3. **各自独立运行**
   - 缓存隔离（不同key）
   - 通知分离（不同标题）
   - 落库区分（strategy字段）

4. **手动对比模式**
   - 用于评估差异
   - 不影响自动执行

这样既保留了原策略的稳定性，又能独立验证长期版的效果，两者互不干扰，便于后续根据实际效果决定是否替换。
